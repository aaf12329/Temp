## 输入、调用及输出

```text
question:str + CLIConfig + 已抓取且通过正文指纹校验的材料
  → workflow.analyze（显式编排）
    → selection.retrieval_settings：有效词表，空列表使用已有默认词表
    → selection.balanced_passages：按文档轮流取段，文档内优先指标数值
    → BGE/关键词 score_passages + supplement_numeric：合并召回，保留原分数
    → 原 evidence.extract_facts：原句、数字、单位、坐标和 pending 状态
    → context.complete_context：关联唯一统计标题，重查范围限制和口径冲突
    → clean_candidates → build_series：检查口径后按年度归组
    → diagnostics.diagnose：定位采集/召回/抽取/口径/序列瓶颈
  → workflow.model → training.prepare_split / train_series
    → 真实时间切分 → GAN门槛及用户选择 → 可选生成 → 审查 → XGBoost
```

新增三个规则模块只有标准库依赖，不加载新模型，不调用API；内嵌爬虫原算法和独立旧研究接口未修改。只有完整CLI/网页管线使用新编排。

网页和CLI共享规则；网页增加数据诊断、排除原因计数和GAN门槛说明，运行消息也记录诊断。CLI在终端及报告中给出原因。

新结果的主要文件：

| 文件 | 内容 |
| --- | --- |
| data/passages.csv | 实际处理的段落、原BGE分数及入选原因 |
| data/information.csv | 匹配原文、关联上下文及候选未解决的限制 |

## 哪些可以关联，哪些必须保留疑问

- 只有标题明确写出唯一年度、且是统计公报/年度报告等时，才可用它补缺失测量年；发布日期、URL年份、年鉴出版年和用户问题都不能代替测量年度。
- 地域只能由该文档标题中的唯一实体关联，不能覆盖句内明确地区，也不能从用户需求复制地域。
- “餐饮收入”指标本身可提供餐饮业主体；仅靠标题判断产业主体的其他情况仍标记待复核。新产业或自定义别名可在JSON的subjects/regions/keywords配置，不自动宣称通用实体识别。
- 紧邻上文最多240字用于发现限额、规模、企业、活动、月度/季度、计划/预测限制；有疑问的数字保留到CSV，不自动混入全年全行业样本。此窗口是保守规则，可能误拦或漏掉更远上下文，仍需要来源复核。
- 原文切片、数字、单位、哈希和pending状态保留；补全记录明确来自标题、指标名还是正文范围。补全后同年同口径有不同数值，会重新标冲突。
- 这些是召回和上下文规则，不是新事实来源，也不证明候选准确。表格的多层表头、无单位数字、扫描PDF、英文指标及复杂跨段语义没有因此自动获得完整支持。

## 为什么仍可能不训练GAN

当前XGBoost自动入口仍是年度单指标序列：至少20个连续真实年度，并满足真实训练不少于10条、验证4条、测试4条及发布时间可见性检查。满足最低年度数也不保证满足全部时间划分条件。

WGAN另外要求每条序列至少64条真实训练行。64指的是划分后训练集，既不是网页数，也不是整张候选表的行数；验证、测试、重复转载、不同城市/统计范围及生成数据都不能混进去凑数。

因此二十多年的年度数据可能能做XGBoost，但无法做WGAN；此时应直接选择真实数据建模。新诊断区分 not_started、available、not_used、generated、dependency_missing、failed，未启动不会显示为训练失败。训练轮数和真实样本门槛是不同问题。

本次不降低64条门槛、不改变原5000轮JSON、不改变真实训练集×5的生成数量或用户两次选择。以后若要用更密集的月度/季度数据，需要同时扩展频率、特征、时间划分及发布滞后逻辑；不能把月度行直接标成年度行，也不能通过合并不同地区来凑样本。
