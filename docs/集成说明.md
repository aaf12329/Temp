# 三模块集成说明

2026-10-21。项目路径以根目录为基准，持久材料引用相对逻辑 data 根。

## 数据形状

```text
CrawlRequest{job_id,project_id,urls[N],...}
 → jobs + job_items[N]
 → Worker → IntegratedCrawler.crawl_one
 → CrawlResult{record_id,source,storage,text_sha256,paragraph_file,tables,...}

ResearchRequest{operation_id,project_id,material_ids[M],mode,config}
 → operations[kind=research]
 → select_materials：归属、状态、路径和正文哈希
 → IntegratedResearch.execute → research_api.analyze
 → {counts,trend_status,run_id,files,human_review_required,mode}

AdvisorRequest{operation_id,project_id,session_id,question,material_ids[0..10],research_id?,demo}
 → operations[kind=advisor]
 → 同项目正文 + 已完成研究摘要
 → IntegratedAdvisor.execute → Advisor.ask
 → {session_id,turn,reply:{content,usage},mode,cited_materials,warnings}
```

采集/研究模块使用旧顶层导入名和全局地址，因此在同一解释器的隔离子进程中 import。载荷仅来自已校验参数，子进程环境不传 API/模型密钥或代理配置。助手直接 import，不另起服务。

## 调用树

```text
main / CLI / celery_app / API
 └─ runtime.create_runtime
     ├─ Jobs / Operations：持久状态、幂等、CAS 租约
     ├─ Materials / Policies：材料和人工站点策略
     ├─ IntegratedCrawler → component.run_component → bridge → webcrawl.api
     ├─ IntegratedResearch → component.run_component → bridge → research_api
     └─ IntegratedAdvisor → advisor_bot.service.build_bot

worker.run_one → Jobs.claim → crawl_one → Jobs.complete
operation_worker.run_operation → Operations.claim → execution.execute_operation
                                                  ├─ research.execute
                                                  └─ advisor.execute
```

Celery 与本机 Worker 共用执行函数。消息只含 ID，Beat 扫描持久待执行/过期行补投，重复投递先经 CAS 领取。采集暂时性失败最多自动重试两次，Celery 不叠加重试。研究崩溃最多恢复两次，每次使用新输出目录；建议崩溃结果未知时停止，避免重复付费。

## 文件与证据

采集先写隔离工作区，再按 SHA256 晋升到 data/raw 和 data/normalized。同 URL 不同内容有不同文件，旧令牌不能覆盖新数据库结果。研究只读登记成功材料，输入副本用短文件名，CSV/JSON 导出还原为平台相对引用，保留 record_id、哈希、来源和原文坐标。

组件原始快照沿用 HTTP 解压后的响应字节；表格 HTML 仍是解析后输出，不能声称原始字节区间保真。文本 PDF 使用原解析器，扫描件没有 OCR。

建议最多 10 条材料，每条最多 4000 字符，总正文预算 12000 字符，并给截断警告。网页只作不可信证据，不执行工具；引用 ID 与当前证据清单比对，不代表人工已审核。聊天和摘要不自动晋升人工事实。

正式 data/advisor/<project_id> 与演示 data/advisor_demo/<project_id> 分开。每个项目中人工事实、会话流水、摘要和操作缓存分别保存。终端与服务共用根环境和配置；独立包继续不依赖 FastAPI。

## 当前边界

已接静态 HTML、文本 PDF、关键词/CPU 向量研究任务和证据建议任务。浏览器/TLS 依赖已在统一环境，但服务网络出口未适配，明确拒绝对应开关；不因安装依赖就声称浏览器二进制及接线通过。

现有 Bearer 调用方视为可信服务端，项目 ID 是材料归属约束。前端接入前须另补用户身份与项目授权。真实 Redis/PostgreSQL 及容器联调未在本机验证。
