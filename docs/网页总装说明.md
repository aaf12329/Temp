## 代码层交付

React/Next.js提供实际研究与独立设计预览。实际请求由Node同源白名单转发，服务token留在服务器；FastAPI验证参数、父任务归属和阶段顺序，沿用既有持久Operations队列与租约Worker，不另建Python环境或另一套任务系统。

```text
PipelineRequest{operation_id,project_id,stage,...}
 prepare: urls[N]+question → collect/analyze/plan
          ├─ data_only → CSV/报告/最终助手
          └─ choice → 等待用户
 gan: parent_id+framework → 真实训练数×5 → 数值检查+t-SNE → 等待用户
 model: parent_id+use_generated → 同批生成文件哈希校验 → XGBoost/真实验证/真实测试 → 助手

Next Route Handler → platform-proxy → /v1/pipeline/jobs
API → Operations.submit → Worker/Celery execute_operation
    → pipeline_service.execute → CLI核心/隔离bridge → 本地模型/最终助手
query → /v1/operations/{id}
files → /v1/pipeline/{id}/files/{name}
```

一次人工动作对应一次幂等操作。父任务必须已完成、同项目、类型正确；不允许未生成即采用。prepare请求可带`extraction=llm|deterministic`，任务目录按`output/web/<模式>/<令牌>`分层；GAN/建模阶段沿用父任务的模式。父产物只读复制，过期Worker不会覆盖另一次决策文件。CSV、PNG、模型和JSON分别放data、charts、models、metadata，统计口径放series，最终报告在任务根目录。metadata/manifest.json记录任务、父任务ID与抽取路径。历史未标记任务仍从data/pipeline读取，不搬动旧结果。最终建模阶段中断不自动重试未知LLM结果。计算阶段使用本机锁。

## GAN规则

生成量固定为清洗后的真实训练表行数×5，不含验证/测试。config/wgan.json仍保留原仓库字节和来源哈希，原n_generate=2000只作来源兼容；实际数量单独记录。5000轮、原网络、设备与图形参数保持。

用户先选择是否训练GAN及框架；生成后打印/显示t-SNE与数值检查，再确认是否采用。拒绝时仅用真实数据继续；采用时读取同一批CSV并校验哈希，不重训。未通过检查的数据不能采用；采用但真实验证未改善时回退真实模型并说明。合成样本不补足建模门槛，不晋升为新证据。
