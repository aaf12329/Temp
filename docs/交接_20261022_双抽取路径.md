## 两条路径

```text
网址 TXT + 一个问题
  → collect（策略/robots/DNS/正文规范化）
  → BGE + 关键词 + 数值邻段召回，先写 information/raw 等 CSV
  → 二选一：
     deterministic：按 rules 正则逐份正文取唯一值
                    → 本地核对唯一年度标题、发布时间、单位换算
                    → 跳过清洗 LLM
     llm：llm_input.csv → 分批无记忆 LLM 清洗
          → 本地字段/引句/数字/单位校验、block_id 重挂、冲突处理
  → finalize（LLM 路径）或 analyze 直接产出（确定性路径）
  → 年度序列 → 20 连续年度 / 10 训练 / 4 验证 / 4 测试 → XGBoost
  → 可选 WGAN（真实训练≥64 才询问）→ 最终趋势 LLM（可关闭）
```

两条路径共用 `clean_candidates → build_series → prepare_split → train_series`，没有第二套门槛或模型。

## 确定性规则怎么配

```json
"extraction": {
  "mode": "deterministic",
  "rules": [
    {
      "subject": "粮食",
      "metric": "production",
      "region": "全国",
      "pattern": "粮食产量\\s*(\\d{4,6})\\s*万吨",
      "unit": "万吨"
    }
  ]
}
```

约束：

- `pattern` 必须且只能有一个捕获组；匹配值按 `unit` 换算到基础单位（`万吨 → 吨`）。
- 同一份正文命中多个不同数值时不自动选取，进入 `extraction.issues`。
- 测量年只来自“唯一 explicit 年度 + 统计公报/年度报告/年报”的标题；发布日期必须存在且不早于测量年末。
- 未配置规则时，确定性路径回退到本地规则且不调用清洗 LLM；可用行可能因复核标记较少，但不会静默编造。
- 新增固定版式来源时，优先新增规则，不要把该来源交给 LLM 搬运数字。

## 验收结果

**自动化测试**

- Python：142 通过、1 跳过（Windows 符号链接权限），约 135 秒。
- 前端：类型检查通过；10 项测试通过；Ruff 全通过。
- 新增用例覆盖：规则抽取/冲突、scope 对象与空 review_reason 归一、同文档 block_id 重挂、变动量不污染总量冲突、网页确定性路径与输出分层。

**26 个粮食公报真实执行**

| 路径 | 可用年度行 | 连续区间 | XGBoost | 测试 MAE | 末值基线 | 结论 |
| --- | --- | --- | --- | --- | --- | --- |
| deterministic | 26 | 2000—2025 | 12/4/4 | 105,727,408 | 17,260,000 | `beats_naive=false` |
| llm | 25 | 2001—2025 | 11/4/4 | 104,327,152 | 17,260,000 | `beats_naive=false` |

- 两条路径都生成了 `xgboost.json`、预测 CSV 和 evaluation/importance/trend/comparison/shap 图。
- LLM 路径本轮 203 个候选、25 个可用、178 个排除、57 块因 32 批预算未处理；2000 年那条被模型自己标了 `needs_review`，保守排除。
- 同一份代码前一次 LLM 运行得到 26 条（2000—2025），说明模型返回有批次差异，不能承诺每次都是同一数量。
- 预测值（如确定性路径 2027 年 595,102,592 吨）低于 2025 年实际 714,880,000 吨，报告已明确标注 `exploratory_unreviewed`、不可靠。

## 已知限制与风险

1. **触发建模不等于预测可用。** 当前特征是绝对值/差分，浅树 XGBoost 无法外推 2015 年训练截止后的增长区间，测试 MAE 约为末值基线的 6 倍。报告已回退到“不可靠”表述，但若目标是可用预测，需要改目标（差分/对数增量）或换线性/ARIMA 类模型，并重新验收。
2. **LLM 输出非确定。** 同一配置两轮 26/25 条；模型可能把“增加量”或“稻谷/肉类”当作粮食总量，本地校验会拒绝，但会带来年度缺口。确定性路径更稳定。
3. **清洗预算会截断。** `llm_cleaning.max_batches=32`、`max_blocks=256`，本轮 57 块未处理。提高预算会增加费用和时间。
4. **确定性规则是按版式写的。** 换网站、换公报模板或指标表述，需要新增/调整规则；没有规则时回退本地规则，不保证达到 20 连续年度。
5. **网页真实 26 网址未做浏览器端到端。** 网页分层与跳过清洗由 HTTP 测试覆盖，26 网址的真实运行走 CLI；两条路径共用同一套分析/建模代码。
6. **旧平铺产物保留。** `output/cli` 根下早期 `report.md/data/charts/metadata/series` 没有搬动；新结果只看 `cli/llm` 和 `cli/deterministic`。
7. **未提交或推送。** 工作区还包含此前会话的未提交改动，提交前需先核对 `git status` 与 `git diff`，不要把旧改动混进本轮提交。
8. **凭据。** LLM 密钥只在根 `.env`；不要写入配置、日志、前端或测试。

## 建议的下一步

1. 若要提升预测可用性：把标签改成同比/差分或对数增量，增加线性/ARIMA 基线，仍用同一时间切分；不要用测试集调参。
2. 若要把真实数据扩展到 1978—2025：先核对 48 个入口的迁移日期与原始发布日，再补确定性规则；不要把链接连续当成数据连续。
3. 若要减少 LLM 归属错误：优先每批 1—2 个块，或继续依赖现有同文档重挂；不要把邻段数字直接接受为匹配段事实。
4. 若要上线网页：补浏览器视觉验收、生产构建和一次真实网页任务；当前只完成了 HTTP 契约测试。
5. 若要提交：先与所有者确认提交范围，只包含本轮相关文件；默认不推送。
