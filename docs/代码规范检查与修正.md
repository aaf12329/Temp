# 代码规范检查与修正

检查日期：2026年10月20日。

依据为用户指定的 CoMind 协作参考索引及其中工程架构、Python 与 PowerShell 规范。本文记录当前工程事实，不复制标准正文。

## 检查结论

上一版通过了功能测试，但**没有完全按这套规范组织**。功能测试通过不能替代规范检查。

重构前检查了32个 Python 文件：27个缺少模块说明，97个函数缺少说明。另有路径位置分散、服务横向依赖共用存储、文件读写入口分散，以及两个维护脚本在导入时执行操作的问题。

已在 `work/before_advisor_source.zip` 备份重构前源码，不包含 .env、真实数据或虚拟环境。原24项功能测试作为重构基线保留。

## 已修正

| 问题 | 实施结果 |
| --- | --- |
| 模块/函数说明不足 | 为生产源码与验收代码补充结构导航、实际调用关系、数据流和函数用途/调用者说明 |
| 数据路径散落 | 新增 app/common/paths.py，集中登记目录、策略、快照、配置与维护产物位置 |
| 文本/JSON 读写分散 | 共用 file_io.py 统一编码回退、UTF-8/LF 与原子写入 |
| 功能层横向引用 storage | 实际存储下沉到 common/storage.py；services/storage.py 只保留显式兼容重导出；业务服务改为依赖共用层 |
| 维护脚本导入即写盘 | init_config.py 与 export_metadata.py 改为显式 main 入口 |
| 重试缺少抖动 | 在原退避基础上加入抖动；自动重试上限和 retryable 约束保持不变 |
| 材料目录内敏感文件 | 除目录边界外，额外拒绝 .env/私钥类引用 |
| 后续容易忘记规范来源 | 新增项目入口 AGENTS.md，只引用原规范并记录本项目分层事实 |

运行时数据文件的位置由地址簿登记；数据库 URL 中指定的位置由配置传入数据库基础设施。测试可以在临时目录构造专用文件用于反例校验。Windows 启动脚本仍需按脚本自身位置寻找项目根和解释器，这是跨语言启动引导位置。

## 当前层次

```text
入口/显式聚合层：main、api/routes、runtime、worker、cli
  ├─ 功能层：services/jobs、materials、policies
  └─ 采集适配器加载入口
       ↓
共用契约/基础设施：common、core、contracts、db、crawler/base
       ↓
标准库 / 第三方库
```

功能服务之间不互相导入。共享错误模型、数据契约、数据库会话与文件设施保持共用层定位。兼容路径仍能导入原 Storage，避免破坏已有调用方。
