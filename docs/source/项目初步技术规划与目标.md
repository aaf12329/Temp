# 产业信息研究平台：初步技术规划与目标

编制日期：2026年10月20日
文档状态：初步讨论稿，技术方案随实际验证调整
首个研究对象：凯里酸汤鱼相关产业

## 一、项目目标与愿景

### 1. 一个规模很大，甚至可以说很宏大的项目

这个项目的野心很大，甚至可以说很宏大：它希望将散落在网页、公开报告、新闻、企业介绍和其他公开材料中的信息，逐步转化为有明确口径、有证据支撑、可被质疑和复核的产业认识，并最终形成可供他人使用的网站。

对于缺少专门官方统计类目的细分产业，项目希望建立一套能够说明“研究对象是什么、统计范围在哪里、数据如何形成、结论依据是什么”的研究方法，再通过软件将这套方法持续执行和改进。项目自行建立的研究口径，需要公开定义、记录版本并接受修订，其适用范围与局限也应明确说明。

宏大愿景需要通过具体对象逐步验证。项目先从凯里酸汤鱼相关产业开始，验证公开信息采集、证据整理、主体识别、口径制定和结果复核是否能够形成有效流程；再通过第二个研究对象检验可复用程度，逐步扩展支持范围。

### 2. 三个递进的业务目标

1. **完成具体产业的研究闭环。** 围绕凯里酸汤鱼相关产业，形成可解释、可复核的材料库、主体清单和研究结果。
2. **提炼可复用的工具包。** 将采集、解析、抽取、证据关联、人工审核和结果导出等通用能力沉淀下来，让产业差异通过规则、配置和必要的适配模块表达。
3. **形成可供他人使用的网站。** 用户能够提交网址或研究任务、查看进度、浏览和修订结果、追溯来源并导出数据。网站逐步开放经过验证的研究能力。

### 3. 人与 AI 协作的方法目标

在实际开发过程中，记录需求、任务边界、接口约定、验证方法和关键决策，逐步形成可复用的人与 AI 协作规范。以减少返工、便于接续工作和定位错误为评价依据。

### 4. 第一阶段希望证明的事情

- 一个范围明确的研究问题，能够通过这套流程得到可复核的结果。
- 计入人工查错、补漏和审核后，整体工作量仍有实际下降。
- 研究者能够看到材料缺失、证据冲突、统计限制和需要人工判断的位置。
- 核心处理能力能够脱离网页独立运行，为后续工具包与网站提供共同基础。

## 二、首期研究范围与结果边界

首期围绕一个具体问题开展，例如：在明确的地域、时间和纳入规则下，建立凯里酸汤鱼相关经营主体清单，并为关键字段保留来源和判断依据。具体地域、时间、字段与纳入规则在实施前确定。

结果中应区分：

- **来源陈述：** 某份公开材料记载了什么，适用时间、范围和单位是什么。
- **整理事实：** 多份材料经过主体识别、字段抽取和去重后形成的记录。
- **估算与推断：** 在特定假设和方法下得到的结果，需要展示假设、方法和局限。
- **待确认信息：** 缺失、冲突或证据不足，仍需进一步核实的内容。

“在公开资料中已发现多少”与“整个产业共有多少”应分别表达。将已发现样本推及产业总体，需要额外的方法和依据。

## 三、初步技术选型与职责分工

| 层次 | 初步选型 | 职责 |
| --- | --- | --- |
| 网页界面 | React + TypeScript | 输入网址、选择研究参数、展示进度、表格筛选、证据查看与人工编辑 |
| 网页框架与网页侧服务 | Next.js | 页面组织与渲染、登录会话、网页侧请求处理、调用 Python 业务接口 |
| 核心业务接口 | FastAPI | 参数与权限校验、项目与任务管理、结果查询、审核修订与规则版本管理 |
| 核心处理程序 | Python | 采集、解析、抽取、主体识别、去重、规则计算与导出 |
| 后台任务执行 | 独立 Python Worker | 执行耗时任务，记录进度、失败原因及运行结果 |
| 持久数据 | PostgreSQL | 保存项目、任务、主体、事实、证据关系、口径版本、修订与结果 |
| 原始材料存储 | 初期本地文件，后续评估对象存储 | 保存网页快照、PDF、图片和导出文件 |
| 任务队列 | Celery + Redis 作为候选方案 | 支持网页提交后的后台任务调度与重试，接入时根据任务特点确认配置 |

React 在 Next.js 项目中使用。FastAPI 与爬虫均采用 Python，按职责划分模块。Flask 保留为备选框架，当前讨论方案以 FastAPI 为主。

TypeScript 可以通过 Next.js 服务端请求 FastAPI，由 Python 服务组织后续处理。浏览器通过服务接口提交任务和获取结果。

### 1. Next.js 与 FastAPI 的边界

Next.js 处理网页侧需求，FastAPI 统一提供核心业务能力。网页登录会话与 Python 接口之间需要明确身份传递方式，FastAPI 对受保护的操作继续进行权限校验。

研究规则、结果修订和核心数据写入集中在 Python 业务层管理。Next.js 通过接口使用这些能力，避免两套服务分别实现相同规则。

### 2. 爬虫与研究规则的边界

爬虫负责获取和初步解析材料，独立的 Python 核心模块负责抽取、主体识别、去重、证据关联和口径计算。

例如，“某家企业是否应纳入研究范围”“企业、品牌、门店如何区分”“冲突数据如何处理”，需要以明确规则和可审核判断表达。核心模块可供命令行、FastAPI 和后台任务共同调用。

### 3. 初期工程组织

初期采用一个 Next.js 项目和一个 Python 项目。Python 项目内部划分 API、采集、解析、研究规则、数据访问和后台任务模块；API 与 Worker 可作为不同进程运行。

先保持清楚的模块边界，后续根据实际负载、部署需要和维护成本决定是否拆分服务。

## 四、一次研究任务的运行流程

1. 用户在 React 页面提交网址、研究对象和所需字段。
2. Next.js 服务端携带用户身份向 FastAPI 提交请求。
3. FastAPI 校验请求，持久化任务记录并安排执行，返回任务编号。
4. Python Worker 获取任务，调用爬虫采集材料，保存来源与原始内容。
5. Python 核心模块执行解析、抽取、主体识别、去重和规则处理。
6. Worker 保存阶段进度、证据关系、处理结果和异常信息。
7. 页面通过业务接口查询状态与结果；首期可采用定期查询，后续按体验需要评估实时推送。
8. 用户核对与修订记录，系统保存修订内容、依据和历史，再生成可导出的结果版本。

长任务在后台执行，接口先返回任务编号。任务状态保存在持久存储中，网页关闭后，后台仍可继续执行。

队列接入时需处理任务已保存但未成功入队、任务重复执行以及进程中断等情况。重试应避免重复生成同一批业务记录，失败任务需要能够定位原因和重新运行。

## 五、可信与可复核的基础设计

### 1. 原始材料可以追溯

记录来源网址、发布主体、可获得的发布时间、采集时间、内容标识及原始材料保存位置。关键字段尽可能关联到正文片段、表格位置或 PDF 页码。

### 2. 事实与证据分开保存

同一事实可能有多份证据，同一来源也可能提供多个事实。转载和引用关系需要尽可能识别，避免把同源报道数量当作独立证据数量。

### 3. 研究口径和处理过程有版本

记录地域、时间、主体类型、纳入与排除条件、字段含义、单位及计算方法。每次运行关联所用规则、处理程序，以及使用 AI 时的模型和提示词版本，为解释结果变化与重新处理提供依据。

### 4. 支持人工审核与不确定性表达

保留数据冲突、缺失、未决判断与人工修订记录。展示结论时同时展示适用范围、依据和局限。使用 AI 抽取或辅助判断时，输出应进入校验与审核流程，保存对应证据。

### 5. 核心记录关系

初期围绕“研究项目—口径版本—运行任务—原始材料—主体与事实—证据关联—审核记录—结果版本”组织数据。最终表结构在首期问题与字段明确后设计。

## 六、分阶段实施规划

### 阶段一：验证一个具体研究问题

确定研究问题、口径与输出字段；准备一批经过人工核对的参考材料；实现可独立运行的 Python 采集和处理流程，产出带来源的主体清单与结果表。

验收重点：关键字段能回到原始证据，缺失与冲突可见，明确记录抽取错误、重复主体和人工审核耗时，并评估现有材料的覆盖局限。

### 阶段二：接入网页并形成工作闭环

接入 Next.js、FastAPI 和后台任务，支持任务提交、进度查询、结果浏览、证据查看、人工修订与导出。

验收重点：网页关闭后任务可继续运行，失败可查且可重试，修订有记录，导出内容与选定结果版本一致。

### 阶段三：验证跨对象复用

选择第二个相近研究对象，检查哪些流程可以复用，哪些部分需要调整规则、字段或采集适配，逐步形成工具包。

验收重点：主要采集、处理、审核与导出流程能够复用；记录新增适配工作量和仍需人工完成的判断，界定工具包的实际支持范围。

### 阶段四：面向他人提供网站服务

根据试用反馈完善账号与权限、任务配额、数据隔离、备份、运行监控和成本记录，逐步开放已验证的能力。

验收重点：新用户能够理解支持范围、提交任务、检查证据和完成修订；能够统计每项任务的运行成本、人工投入与结果质量。

## 七、下一步需要确定的事项

1. 首个研究问题，以及对应的地域、时间和纳入规则。
2. 第一张结果表的字段、字段定义与证据要求。
3. 首批公开来源，以及各来源允许的访问方式、频率和技术适配需求。
4. 人工参考样本与质量评估方法，尤其是抽取准确性、主体去重和审核工作量。
5. AI 在抽取、分类和辅助判断中的具体用途，以及调用成本与人工审核边界。
6. 第一阶段的使用环境、部署方式与预计任务规模。

当前优先完成研究问题和口径的定义，再用一个可复核的实际结果检验技术方案。
