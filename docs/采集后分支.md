# 采集后再选择

本次范围以所有者最新澄清为准：**只在网页爬完后加选择，教材分支暂时停在材料，不继续实现定制解析。**

```text
网址清单[N] + 需求[字符串]
    │
    collect：站点/robots/响应检查、下载及爬虫已有的正文整理
    │
    来源记录[N成功] + 原件/正文/已有表格 + 逐网址访问记录[N]
    │
    用户选择（此前不运行研究模型、LLM或数值抽取）
    ├─ 教材分支 → materials_ready：保存材料并停止，后续方案待定
    └─ 原自动流程 → 复用已采正文 → BGE/关键词 → CSV → LLM清洗
                                        → 原有缺失诊断/WGAN选择/XGBoost/趋势
```

这里的“采集完成”包含现有爬虫自带的HTML正文规范化、段落/表格保存和元信息检查，不代表已完成产业数值提取。不会将正文文件标成原始HTML。`collection.json` 对每份来源标注 `raw_available`，包内文件逐个带哈希。

## 网页使用

1. 输入网址清单与需求，开始采集。
2. 采集完成后显示“继续原自动流程”和“进入教材分支，先查看材料”。
3. 选教材分支，仅展示来源、失败原因与可下载材料，停在这里；不显示“数据不足不能建模”一类尚未判定的结论。
4. 下载 `data/sources.zip`，包内 `data/raw/` 是已取得的HTML/PDF原件，`data/normalized/` 是爬虫保存的正文、段落和表格。索引、原采集记录和访问记录也在包内。

API/Worker调用树：

```text
LiveResearch.start → stage=collect → execute → collect + save_collection
    → branch_choice（持久操作完成，等待用户，不占Worker）
LiveResearch.onRoute → stage=route + parent_id
    ├─ extraction=textbook → 只复制父检查点 → materials_ready
    └─ extraction=llm → 校验同批正文哈希 → stage_records → 原分析流程
```

采集父任务只读；不同选择使用不同结果目录。选择原流程不重爬，正文若被修改则报错。教材检查点不能直接提交GAN或XGBoost操作。新入口产物位于 `output/web/collection/<令牌>` 与 `output/web/textbook/<令牌>`，原流程继续在 `output/web/llm/<令牌>`。

## 终端使用

正常启动CLI后，先输入网址文件和需求，等采集结束后再选 `1`（继续）或 `2`（教材暂停）。回车默认暂停。无交互运行可显式指定：

```powershell
.venv\Scripts\python.exe -m app.pipeline_cli --urls-file "examples/research_sources/01_公报网址_2000-2025.txt" --query "粮食产量" --after-crawl textbook
```

网址清单路径换成自己的实际文件。材料检查点在 `output/cli/collection`；选择继续后原流程写入既有的 `output/cli/<抽取模式>`。教材暂停结果状态为 `materials_ready`，不调用分析、清洗、训练或最终助手。底层 `run()` 为兼容已有自动化调用默认继续；命令行 `main()` 默认采集后询问。

旧 `prepare` HTTP入口及 `--extraction deterministic` 正则抽取功能保留兼容，不作为本次教材分支的实现；旧任务与旧输出不会自动重算。后端修改后需在原窗口停止并重新一键启动，避免端口重复占用。
