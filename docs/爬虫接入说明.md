# 爬虫接入说明

原始合同为 `source/爬虫标准API接口.md`，本文件说明服务框架的接入方式。

## 适配器入口

```python
from app.contracts.crawler import CrawlRequest, CrawlResult, ProbeRequest, Profile, SitePolicy
from app.crawler.base import CrawlContext

class MyCrawlerAdapter:
    def probe(self, request: ProbeRequest, policies: list[SitePolicy]) -> list[Profile]:
        # 接入已有 probe 实现；结果按输入 URL 顺序返回。
        raise NotImplementedError

    def crawl_one(self, request: CrawlRequest, url: str, context: CrawlContext) -> CrawlResult:
        # 接入已有采集函数。每次处理当前 url，保留原 job_id/project_id。
        # 若已有 crawl 接收 URL 列表，可构造只含当前 URL 的请求后读取唯一结果。
        raise NotImplementedError

def create_adapter():
    return MyCrawlerAdapter()
```

将自己的包安装在根目录 `.venv`，或将模块放在项目可导入路径内。配置 `.env` 的 `INDUSTRY_CRAWLER_ADAPTER=模块路径:create_adapter`。API 与 Worker 应使用同一配置；工厂在各自进程初始化，适配器不得依赖 API 进程的内存状态。

HTTP 和后台处理均为同步 Python 接入口；异步爬虫可在适配器内部封装事件循环。API 的同步路由由框架在线程池中执行，适配器若保存可变共享状态需自行保证线程安全。

## 网络访问与站点策略

在 `data/policy/site_policy.json` 人工添加条目，例如：

```json
[
  {
    "host": "由人工确认的域名",
    "allowed_paths": ["/由人工确认的路径前缀/"],
    "disallowed_paths": [],
    "min_interval_s": 1.5,
    "preferred_tool": null,
    "requires_login": false,
    "has_pdf": true,
    "note": "填写实际访问依据及限制"
  }
]
```

框架初始化只创建空数组，不自动添加、修改或覆盖条目。Worker 执行前检查主机策略、登录要求和路径前缀；适配器对 probe 和 crawl 都必须继续落实这些限制。

- `respect_robots` 恒为 true，适配器应实际检查 robots，并区分不允许与无法判定。
- 限速采用请求参数、人工策略与 robots crawl-delay 中的最大要求；多 Worker 运行时需要跨进程共享限速状态。
- 重定向后的来源需要重新检查策略、robots 与允许路径，禁止借重定向绕过限制。
- 抓取任意用户提供的 URL 前，校验 DNS 和目标地址，阻止内网、回环、链路本地及云元数据目标；每次重定向和重新解析均需校验。
- 配置真实项目 User-Agent 和联系方式；服务不会编造联系信息。
- HTTP 连接、读取、浏览器渲染与 PDF 处理都需要有限超时及资源边界。

上述网络能力仍待真实适配器实现，本项目未宣称已完成抓取安全验收。

## 材料身份与文件

- `record_id` 使用 `app.contracts.crawler.record_id_for(job_id, url)`，原始 URL 字符串不自动规范化。
- 必须保留 `job_id`、`project_id`、请求者、规则版本与真实爬虫程序版本；来源缺失时返回 null。
- `context.data_dir` 是当前配置的数据根目录，适配器必须使用它，不得将根目录硬编码成工作目录。
- 规范化正文引用暂约定为 `storage.text_path`，PDF 也支持 `pdf.text_path`；这一子字段在原合同中未展开，后续按完整合同校准。
- 段落使用 `paragraph_file`；表格使用 `json_path`、`csv_path` 和原始 `html_path`；下游材料接口只提供 normalized 内的文件。
- 相对引用可使用 `data/normalized/...` 或 `normalized/...`，与配置的数据根目录映射。
- 正文以 UTF-8 保存，明确使用 LF 换行；字符偏移和 `text_sha256` 应依据最终实际保存的正文计算。Windows 默认文本写入可能转换换行符，请使用 `write_bytes(text.encode('utf-8'))` 或明确指定 `newline='\n'`。
- 段落偏移为 Python 字符串切片的 `[char_start:char_end]`，页码从 1 起，段号从 0 起。
- PDF 无文本层需按合同返回 `E_PDF_NO_TEXT`，表格保留合并结构，原始材料保持字节保真。

仅 URL 哈希命名与多次采集原始字节不可变之间存在尚未解决的版本管理问题，详见缺项文档。真实爬虫接入前需确定快照保存策略。

## 错误和重试

优先返回带 `error` 的 `CrawlResult`，或抛出带明确 `retryable` 的 `ServiceError`。框架仅对可重试失败自动重试两次，包含首次执行最多三次。未知异常按不可重试的适配器错误记录，日志保留堆栈。

显式调用 retry 接口只重新安排可重试的失败项，开启新的尝试周期，保持同一材料主键。成功项不重新执行。Worker 中断可能导致至少一次执行，适配器需要自行保证落盘重入安全。

当前 `status` 保持开放字符串。服务暂按 `error` 与已知 `verdict` 计算 counts：有错误为 failed；robots 禁止/未知、登录墙、blocked、dynamic 作为 skipped；有效 PDF 为 ok_pdf，其余可用材料为 ok。这是服务侧过渡规则，完整四态定义到位后再对齐。

测试目录中的适配器生成明确标注的本地测试材料，不可配置为实际研究数据源。
