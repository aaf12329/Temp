# 爬虫数据分析使用说明

## 运行

在 Crawler 根目录执行，解释器使用 `myvenv/Scripts/python.exe`：

```powershell
# 首次安装；本机 pip 代理问题时先设 NO_PROXY=*
.\myvenv\Scripts\python.exe -m pip install -r requirement.txt
# 首次显式下载固定版本的 CPU ONNX 向量模型（约 24MB）
.\myvenv\Scripts\python.exe src\main.py model-setup
# 采集沿用原命令；增量、robots、站点限速和断点账本继续生效
.\myvenv\Scripts\python.exe src\main.py crawl --incremental --no-proxy
# 分析本地已采正文；建议每次给新的 --out 目录
.\myvenv\Scripts\python.exe src\main.py analyze --out data\research\run-001
# 无向量环境时可显式只做关键词匹配
.\myvenv\Scripts\python.exe src\main.py analyze --lexical-only --out data\research\lexical-001
# 查看独立 API 能力
.\myvenv\Scripts\python.exe src\main.py research-api
```

现有旧 `parse` 命令读取旧快照字段，不适用于新 CrawlResult。新研究流程直接读 normalized 正文，使用 `analyze`。

## 可调整输入和程序结构

`config/research.json` 是研究口径与召回配置：keywords、自然语言 queries、主体/地域名单、rule_version 和预测截止日。subjects/regions 可改成 `{规范名:[原文别名]}`，未明确的口径不靠模型猜测。更改后使用新输出目录，保留旧结果。

```text
pages.json: CrawlResult[N]
  -> evidence.load_corpus: documents[D], passages[P], issues[I]
  -> retrieval.Encoder.encode: [P,512] CPU CLS/L2 向量
  -> retrieval.score_passages: 关键词命中 OR 余弦相似度 >= 阈值
  -> evidence.extract_facts: pending facts[F] + 精确原文坐标
  -> review.apply_reviews: 独立人工审核决定
  -> evidence.build_series: approved 同口径年度序列[S]
  -> trend.analyze_series: 逐序列滚动回测及数据缺口
```

```text
入口 main.py -> research_api.py（显式编排）
                ├─ evidence.py（语料/证据/可比序列）
                ├─ retrieval.py（CPU 语义召回）
                ├─ review.py（审核决定）
                └─ trend.py（滚动回测）
     main.py -> assets.py（显式模型准备）
             -> llm.py（可选 DeepSeek 建议）
功能模块不互相导入；I/O 统一由 webcrawl.io_utils；路径由 Path_Store 管理。
```

语义阈值 0.64 经高分候选的小范围 Agent 抽查后用于补查，**尚未做基准校准**；分数不是相关概率。`semantic_exclude_keywords=["酸菜鱼"]` 阻止这个已知混淆项仅凭语义分数入选；同段明确命中酸汤等关键词时仍保留比较材料。相关性质量须用独立人工标注的正负样本评估 precision/recall 后再调阈值，不能以高分样本抽查估计整体召回率。CPU 4 线程、batch 8、最大 256 token；超过长度的片段模型截断，完整证据仍保留。

## 输出与审核

输出 documents.csv、passages.csv、facts.csv、review_template.csv、series.csv、issues.json、manifest.json、analysis.json、trend.json、report.md。CSV 带 UTF-8 BOM，JSON 保留完整正文、source_variants、列表类型与模型指纹。

facts.csv 是**机器候选**，不是已校验事实。对照原始来源审查主体、年份、地域、量纲和统计范围；review_template.csv 只应用 `fact_id/review_status/review_note`，修改其中数值或证据不会覆写原候选。缺字段或非精确值仍被阻止组序列，不能单靠 approved 绕过。

```powershell
.\myvenv\Scripts\python.exe src\main.py train `
  --analysis data\research\run-001\analysis.json `
  --reviews data\research\人工审核.csv `
  --out data\research\review-001
```

所有审核、manifest 和实际序列保留在训练报告中；原始 analysis.json 不被修改。冲突数值须明确拒绝不适用候选；不能自动平均或当独立样本增加训练量。

## 趋势模型的边界

目前实现年度单指标 XGBoost 回归，固定参数、CPU hist、4 线程，与“最后已知值不变”的基线比较。至少 20 个连续同口径年度，每折至少 10 个当时已发布的训练标签，最后至少 4 个滚动留出起点；缺年、不足、混口径、未来发布或过旧数据均显示具体缺口。20 年仍不自动保证可靠性，这是最低验证门槛。

每折在当年年末取当时可得的历史指标，预测下一年；训练和特征同时按 published/known_at 限制，不能拿后来公布的数据回测过去。预测截止时间记录在配置。MAE 优于基线时状态 validated，仅表示这组有限留出数据通过比较；未优于基线为 exploratory_model，不发布可持久化模型。

模型尚未包含月度需求、电商销量、成本与竞争等外生特征，当前不能凭新闻篇数判断产业前景。需要先确定预测目标和获取持续可比的观测数据；本轮真实数据若不足，会返回 insufficient_data。

## 可选 DeepSeek

`.env` 设置 DEEPSEEK_API_KEY、DEEPSEEK_BASE_URL、DEEPSEEK_MODEL；默认使用官方接口与 deepseek-flash。`.env` 已忽略，示例不含密钥。

```powershell
.\myvenv\Scripts\python.exe src\main.py ai                    # 查看可用模型
.\myvenv\Scripts\python.exe src\main.py ai --suggest --limit 3 # 显式付费调用
```

每次默认只发 3 个片段，最多 10 个，每段最多 240 字，最多 1000 输出 token；这里只发送所选公开网页文本。结果保存 llm_suggestions.json，包含 token usage、模型及提示版本，始终待审核。原文证据、数值和口径匹配失败的建议丢弃并记录原因，不进入建模输入。

资料：[BGE 原始模型](https://huggingface.co/BAAI/bge-small-zh-v1.5)、[量化版](https://huggingface.co/Xenova/bge-small-zh-v1.5)、[XGBoost](https://xgboost.readthedocs.io/en/stable/parameter.html)、[DeepSeek](https://api-docs.deepseek.com/)。
