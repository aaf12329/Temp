## 已实现的 Python 接口

采集接口仍为 `src/webcrawl/api.py` v1.3：`probe/plan/crawl/expand/resume_job/job_progress/read_material/site_policy/write_site_policy`。

研究接口为 `src/research_api.py` v1.0，属于**显式入口编排层**：

```python
import research_api  # 将 Crawler/src 加入专用环境的 PYTHONPATH

research_api.capabilities()
research_api.analyze({
    "config_path": "config/research.json",
    "index_path": "data/raw/pages.json",
    "output_dir": "data/research/run-001",
    "mode": "semantic",  # lexical 为显式降级，不伪造语义分数
})
research_api.train({
    "analysis_path": "data/research/run-001/analysis.json",
    "reviews": "人工审核后的CSV路径",
    "output_dir": "data/research/review-001",
})
```

`analyze` 也接受内存 `records: CrawlResult[]`，替代 `index_path`。所有方法返回可 JSON 序列化的同一壳：

```json
{"api_version":"1.0","status":"ok","data":{},"error":null}
```

错误返回 `status=error, data=null, error={code,message,retryable}`。`analyze/train` 的计算成功与趋势报告状态分开：无足够数据是 `data.trend_status=insufficient_data`，不是网络错误。

`analyze` 的 data 含 counts、paths、trend_status；完整证据保存在 paths.analysis 指向的 JSON。`train` 的 data 含 trend、series_rows；trend 含逐序列回测报告、审核决定、分析 manifest、实际系列数据与审核文件 SHA256。

## 材料和事实合同

| 对象 | 必须保持的含义 |
|---|---|
| 材料身份 | `record_id/job_id/url` 沿用采集结果，不使用新 UUID 替换旧 ID |
| 正文版本 | `text_sha256` 对应本轮读取的最终 Unicode 正文；不匹配则拒绝 |
| 证据坐标 | `char_start/char_end` 为 Python 字符串左闭右开切片；前端 JS UTF-16 不能直接照搬非 BMP 偏移 |
| 片段 | `passage_id` 由正文指纹和偏移稳定生成；同文跨 URL 保留 source_variants |
| 数字事实 | `fact_id`、原文与数值坐标、指标、单位、年份、地域、主体、claim_type、uncertainty_flags |
| 人工决定 | `fact_id/review_status/review_note`；pending、approved、rejected，非 pending 必填理由 |
| 可比序列 | `series_id/scope/period(int)/value/known_at/evidence_ids`；按主体、指标、地域、时间口径、单位隔离 |
| 模型 | 状态、预测截止日、特征、逐折标签/发布时间审计、基线与模型指标；通过基线门槛才提供 model_json |

规则未自动认定经营主体或企业总量；来源中的“酸汤产业”与“酸汤鱼”、产值与营收、政策目标与观测、全省与全州保持不同口径。

DeepSeek 的 `chat` 按 CoMind 返回 `content/reasoning/usage/tool_calls` 四字段。`suggest` 只产生独立 pending 建议，原文证据必须逐字命中，不自动转成 approved 事实。读取后端材料时必须传递来源与版本，不只传脱离上下文的数字。
